# Prompt-Mail 产品需求文档（PRD）

> **项目名称**：Prompt-Mail — 第三方邮箱接入与 AI 辅助邮件系统
> **文档版本**：v1.0.0
> **创建日期**：2026-05-05
> **产品经理**：许清楚（Xu）

---

## 一、产品目标

| # | 目标 | 说明 |
|---|------|------|
| G1 | **统一收发邮件** | 通过 IMAP/SMTP 协议接入阿里邮箱与 QQ 邮箱，在本地 Web 应用中实现邮件的收取、浏览与回复，替代传统邮件客户端的日常使用场景 |
| G2 | **AI 赋能邮件回复** | 接入 OpenAI 标准兼容的大模型服务，基于邮件全文上下文一键生成回复内容，降低邮件回复的时间成本与认知负担 |
| G3 | **轻量本地化部署** | 作为纯本地启动的项目，零云依赖、零安全门槛，用户可快速配置即用，同时通过 localStorage 实现数据缓存以提升体验流畅度 |

## 二、用户故事

### US-1：首次配置邮箱
> 作为用户，我希望在配置页面选择阿里邮箱或 QQ 邮箱，填写 IMAP/SMTP 账号信息后一键测试连接，确认无误后保存配置，以便后续直接在系统中收发邮件。

### US-2：浏览与管理邮件
> 作为用户，我希望在邮箱列表页左侧看到最近 50 封邮件的列表，支持按已读/未读筛选，点击某封邮件后右侧展示完整内容（含富文本正文与附件），以便高效浏览日常邮件。

### US-3：AI 辅助回复邮件
> 作为用户，我在阅读邮件后希望点击「AI 生成」按钮，系统将邮件完整上下文（标题、发件人、正文等）发送给 AI，一键生成回复内容，我可以直接使用或编辑后再发送，以大幅减少回复时间。

### US-4：配置 AI 服务
> 作为用户，我希望在配置页面填写 OpenAI 标准兼容的 API 地址和密钥，并设置通用提示词（如回复风格、语言偏好等），以便 AI 生成的回复更符合我的个人习惯。

### US-5：附件按需查看
> 作为用户，我希望邮件列表只预加载附件元数据（文件名、大小、类型），当我点击某个附件时才按需拉取实际内容并在线查看，以避免不必要的流量与等待。

## 三、竞品分析

| # | 产品 | 定位 | 优点 | 缺点 | 与本项目关系 |
|---|------|------|------|------|-------------|
| 1 | **Thunderbird** | 桌面邮件客户端 | 开源免费；支持 IMAP/SMTP；扩展生态丰富；离线可用 | 界面陈旧；无 AI 集成；配置门槛较高 | 本项目对标其收发能力，但以 Web 形态呈现并增加 AI 回复 |
| 2 | **Spark Mail** | 智能 AI 邮件客户端 | AI 邮件摘要与模板回复；跨平台；设计现代 | 云端依赖强；隐私顾虑；AI 功能需订阅；国内邮箱适配差 | 本项目采用本地部署解决隐私问题，AI 功能免费自建 |
| 3 | **Outlook Desktop** | 企业邮件客户端 | 功能全面；Exchange 深度集成；规则/筛选强大 | 臃肿；非国内邮箱适配一般；无 AI 回复生成 | 本项目聚焦国内邮箱（阿里/QQ），更轻量 |
| 4 | **Foxmail** | 国内老牌邮件客户端 | 国内邮箱适配好；界面简洁；免费 | 无 AI 功能；技术栈老旧；扩展性差 | 本项目采用现代前端技术栈，面向开发者群体 |
| 5 | **Mailspring** | 开源现代邮件客户端 | 开源；界面美观；多账户；快捷操作 | AI 仅限付费；IMAP 同步偶有问题；中文支持一般 | 本项目 AI 自建可控，专注中文邮箱生态 |
| 6 | **Gmail Web** | Web 邮箱 | 生态完善；AI 写作辅助（Gemini）；搜索强大 | 国内无法直连；不支持阿里/QQ 邮箱 | 本项目解决国内邮箱接入痛点 |
| 7 | **简信 (Spark 中国版)** | 国内智能邮件 | 中文优化；AI 辅助；移动端体验好 | 桌面端缺失；AI 功能有限；依赖云端 | 本项目本地部署，无云端依赖 |

**竞品分析总结**：当前市场上缺少一个**本地化部署 + 国内邮箱适配 + AI 回复生成**三位一体的轻量邮件工具。本项目正是填补这一空白。

### 4.2 Vite Oxc 配置规范

Vite 最新版本已将 `esbuild` 选项标记为废弃（deprecated），内部自动转换为 `oxc` 选项。本项目需遵循以下配置：

```typescript
// vite.config.ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  oxc: {
    // 默认处理 ts, jsx, tsx 文件，无需额外配置即可使用
    // 如需自定义 JSX，可配置：
    // jsx: {
    //   runtime: 'automatic', // React 17+ 推荐使用 automatic
    // },
    // 如需自动注入 React 导入（使用 classic runtime 时）：
    // jsxInject: `import React from 'react'`,
  },
  server: {
    proxy: {
      // 代理 Node.js 后端接口
      '/api': {
        target: 'http://localhost:3001',
        changeOrigin: true,
      },
    },
  },
})
```

**关键注意事项**：
- 不再使用 `esbuild` 配置项，统一使用 `oxc`
- `oxc` 默认启用，处理 `.ts`、`.jsx`、`.tsx` 文件
- 可通过 `oxc: false` 完全禁用 oxc 转换（不推荐）
- 可通过 `oxc.include` / `oxc.exclude` 控制文件范围（支持 regex / picomatch 模式）
- 完整选项参考 [Oxc Transformer 文档](https://oxc.rs/docs/guide/usage/transformer)

### 6.4 关键交互流程

#### 邮件回复流程

```
用户点击邮件 → 右侧展示详情 → 用户点击「AI 生成」
     │
     ▼
前端发送请求: POST /api/ai/generate
Body: {
  subject: "项目周报",
  from: "zhangsan@example.com",
  body: "<邮件正文HTML>",
  prompt: "通用提示词内容"
}
     │
     ▼
Node.js 后端 → 调用 OpenAI 兼容 API → 返回 AI 回复文本
     │
     ▼
前端将 AI 回复内容填充至 Tiptap 编辑器
     │
     ▼
用户可编辑 → 点击「发送回复」
     │
     ▼
前端发送请求: POST /api/mail/reply
Body: {
  to: "zhangsan@example.com",
  subject: "Re: 项目周报",
  body: "<编辑后的回复HTML>",
  inReplyTo: "<Message-ID>"
}
     │
     ▼
Node.js 后端 → nodemailer SMTP 发送 → 返回发送结果
```

## 八、数据模型

### 8.1 邮箱配置（EmailConfig）

```typescript
interface EmailConfig {
  id: string
  type: 'aliyun' | 'qq'
  imapHost: string
  imapPort: number
  smtpHost: string
  smtpPort: number
  account: string
  authCode: string      // 授权码（非登录密码）
  createdAt: string
  updatedAt: string
```
